# 编辑用户消息并重新发送

[English](edit-user-messages.md) | [简体中文](edit-user-messages.zh-CN.md)

已连接的 Codex、Claude Code 和 DeepSeek 会话支持“编辑消息”。选择“保存并重新发送”后，会从目标用户消息之前的历史重新开始：当前会话跟随编辑后的分支，原始完整会话保留为独立会话。

编辑器保留文本、文件引用和图片附件。取消编辑不会改变会话或主输入框草稿。请求失败时保留编辑草稿；如果分叉成功但发送失败，重试会发送到已经建立的编辑分支，不会再次分叉。默认不修改工作区文件；勾选“同时将文件恢复到此消息之前”后，需要先预览检查点记录的文件变化。

## 实现方式

- 使用独立的桌面/HTTP 命令 `acp_edit_fork`。旧服务器会拒绝未知命令，不会忽略编辑参数而错误地从会话末尾分叉。
- 请求携带预期会话 ID 和选中的已解析用户消息。后端在操作前校验消息 ID、角色、时间戳和内容。
- 编辑第一条消息时创建新会话；编辑后续消息时，在前一条助手消息处原生分叉，并验证新分支精确保留目标消息之前的历史。连接沿用模型、模式和 MCP 配置。
- 本地消息通过持久化的客户端消息凭据绑定到发送前的完整历史、会话和工作区。文本规范化复用各提供方解析器的规则，不依赖时间窗口或同文案搜索。无法区分的重复未落盘提示词会被拒绝，需要重新加载原生历史。根据当前文件推算的补丁展示行号不会改变凭据身份。
- 切换分支时，一并清理旧的实时、乐观更新、后台和元数据缓冲区，并使旧历史请求失效。
- 重新发送携带 `expectedSessionId`，由发送锁保护目标校验，防止会话切换后误投递到其他分支。

## 使用边界

- 只能编辑自己控制的空闲连接；不能有正在提交的本地消息或排队消息。回复尚未结束时，先停止回复。
- 精确历史分叉要求适配器声明支持 `session/fork`，并至少使用 Claude ACP 0.75.1、Codex ACP 1.8.0 或 DeepSeek ACP 0.8.0。
- 连续用户消息、系统消息边界、无法验证的消息身份，以及原生分叉保留了超出要求的完整 Agent 回合等情况，会被拒绝并保留草稿，不会回退到包含旧后续上下文的分支。
- 附件原始字节不可用时，需要先恢复附件再重新发送。

## 验证与复现

本改动包含确定性测试和显式启用的真实适配器测试。真实测试使用临时工作区和内存中的 Codeg 数据库，不替换已安装应用。原生适配器沿用已有认证，在其原生历史目录中留下小型测试会话。真实测试会消耗模型额度，必须同时指定 `--ignored` 和 `CODEG_MESSAGE_EDIT_LIVE=1`。

在 `src-tauri` 目录运行确定性 ACP 测试：

```sh
cargo test --no-default-features --features server-bin --lib acp::
```

真实适配器测试的 PowerShell 示例：

```powershell
$env:CODEG_MESSAGE_EDIT_LIVE = '1'
$env:CODEG_MESSAGE_EDIT_LIVE_PROVIDERS = 'claude,codex'
$env:CODEG_MESSAGE_EDIT_LIVE_RESTORE = '1'
cargo test --no-default-features --features test-utils --test message_edit_live -- --ignored --test-threads=1 --nocapture
```

额外设置 `CODEG_MESSAGE_EDIT_LIVE_CANCEL=1`，可检查取消后的后台任务结束、文件恢复以及恢复后连续 35 秒没有继续写入。脱敏的 Claude 分叉时间戳回归测试不需要真实模型或认证。

验证结果：

- 前端全量测试通过 8460 项；后续消息规范化专项通过 7 项；最新编辑弹窗、身份、传输和十种语言专项通过 84 项。
- TypeScript、改动文件 ESLint、Next.js 静态生产构建均通过。完整前端 lint 在与 CI 一致的 LF 换行检出方式下通过。
- Windows 服务器库全量通过 4635 项，包含 1867 项 ACP 回归；Linux 文件检查点回归通过 58 项。桌面和服务器编译检查通过。
- 服务器模式严格 Clippy 使用 `-D warnings` 通过，没有告警豁免。
- 桌面 CI 命令 `cargo clippy --all-targets --features test-utils -- -D warnings` 也已通过。为保持现有扁平 IPC 参数格式，四个 Tauri 命令边界保留了注明原因的局部 `too_many_arguments` 例外，其余检查问题已修正。编译检查使用的伴生进程占位文件不代表已经构建可分发安装包。
- 真实 Claude Code 和 Codex 测试验证了持久消息身份、首条和历史消息编辑、丢弃后续上下文、保留原始会话、拒绝向过时会话发送及重试，以及文件字节精确恢复。
- 真实 Codex 取消场景通过：原生命令约 31 秒后结束，期间拒绝恢复；两个实际写入的文件均被恢复，恢复后观察 35 秒未出现新写入。

## 文件恢复

检查点记录默认关闭。在编辑对话框中开启后，仅为后续 Claude Code、Codex 或 DeepSeek 提示词记录。关闭记录后，已保留检查点仍可用于恢复。状态区显示记录数量、存储量和最近的捕获错误；清理操作回收过期和废弃记录。

Codeg 在工作区外保存按内容寻址的回合前后字节快照，不修改 Git 暂存区、HEAD 或分支。编辑消息时可以恢复该提示词之前的文件，包括被删除的文件、原有未提交或未跟踪内容、二进制字节及文件模式。回合中新建的文件，只有当前内容仍与记录一致时才会被删除。

文件恢复是可选操作。勾选后先获取文件预览；存在冲突或缺少覆盖时，禁止编辑与恢复的组合操作。写入前，后端会再次依据当前文件校验预览令牌。受影响文件如果在回合之间或最后一个检查点之后被修改，会产生冲突；未受影响文件保留不变。这是“回合期间工作区变化”的快照，**无法单独区分同一回合中外部编辑器产生的修改**。

普通发送仍可并行。同一工作区或嵌套工作区内已知的重叠回合，会使相关检查点失效。恢复要求重叠的 Codeg 连接没有前台或后台任务，并在操作期间阻止新提示词。恢复过程中不要让另一个 Codeg 进程或外部程序同时写入这些文件；路径校验不是对抗恶意并发操作系统文件替换的沙箱。

覆盖从开启记录后开始。取消或失败的回合，在原生提供方实际结束且后台任务空闲后也可以形成检查点。原生 shell 命令可能不会随取消立即结束；收到取消响应后，连接继续处理后台事件，在已知后台任务结束且事件流稳定一秒后才捕获快照。最终捕获期间再次出现活动会拒绝发布。等待最多两分钟，超时或与其他工作重叠时不提供覆盖。这依赖适配器上报其原生后台任务；ACP 无法证明未上报的外部进程已经停止。

发送前取消会清理未使用的检查点和消息身份预留。旧消息、回合中途追加指令、重叠回合，以及不能无损匹配到原生历史的 `resource`/`resource_link` 附件不具备可用覆盖。成功的编辑分叉会继承保留历史已有的检查点。普通文本内文件引用和图片附件仍受支持。

只覆盖工作区内的常规文件。工作区 `.gitignore`、Git 内部目录、嵌套仓库和常见依赖/构建目录不在覆盖范围内。嵌套仓库边界变化会使覆盖失效；不读取全局 Git 忽略配置或 `.git/info/exclude`。符号链接、目录联接、硬链接、非常规条目、非 UTF-8 路径、忽略策略变化或大小超限会使检查点不可用，而不是悄悄保存部分覆盖。

资源限制：每个文件最多 16 MiB，每次快照最多 128 MiB、20000 个文件，每个规范化工作区最多 512 MiB 对象。自动回收保留最多 100 个近期已完成回合，最长 30 天，配额不足时逐出较旧覆盖。分叉复制历史时临时允许最多 201 条元数据记录，清理或下次捕获会恢复常规保留上限。正在捕获的对象和恢复日志两侧所需的字节不会被回收。

回合前后扫描各有两秒的协作式预算。停止操作会在原生发送前取消准备工作。过大、过慢或取消的扫描会报告覆盖不可用，不会生成部分检查点；操作系统文件调用本身不能被中途打断。关闭记录时不扫描工作区文件内容。

快照存放在 `CODEG_HOME` 下的 `file-checkpoints/<workspace-hash>`；未设置时，服务器模式使用 `CODEG_DATA_DIR`，否则使用 `~/.codeg`。每个工作区使用操作系统锁、带哈希校验的不可变对象、原子元数据和持久恢复日志。完整恢复计划只写一次，每次文件写入前仅更新与事务绑定的小型进度记录。失败事务会删除自身临时继承的元数据，旧版恢复日志仍可读取。

写入工作区之前，日志记录原始/分叉会话 ID 和会话数据库行。发生中断后，“恢复中断的文件还原”根据数据库区分已经提交的恢复与需要补偿的操作。如果文件已被再次修改或会话状态无法确定，会保留日志供人工处理。分叉成功而重新发送失败时，重试只发送消息，不会再次恢复文件。

## 官方参考与范围

- [Claude Code 检查点](https://code.claude.com/docs/en/checkpointing)：提示词前建立检查点，可选择代码/会话恢复，对 Bash、多数子代理、回合中途消息和链接路径有覆盖限制。
- [Claude Agent SDK 文件检查点](https://code.claude.com/docs/en/agent-sdk/file-checkpointing)：`enableFileCheckpointing`、用户消息 UUID 和 `rewindFiles`；文件恢复独立于会话回退。
- [Codex App review](https://developers.openai.com/codex/app/review/)：文件/代码块还原是 Git 操作。
- [Codex app-server](https://developers.openai.com/codex/app-server/)：会话 rollback 与文件恢复分开。
- 官方历史版本的 [UndoTask](https://github.com/openai/codex/blob/rust-v0.104.0/codex-rs/core/src/tasks/undo.rs) 与 [ghost snapshots](https://github.com/openai/codex/blob/rust-v0.104.0/codex-rs/utils/git/src/ghost_commits.rs) 为工作区检查点方案提供参考。这些链接指向明确的历史标签，不代表当前 Codex App 内部实现。

已安装 ACP 适配器没有共同的文件回退请求。本实现把官方检查点的操作语义落实在 Codeg 内部，不修改适配器包，也不声称调用了不存在的原生回退 API。工作区快照可以覆盖 shell 产生的变化，范围与 Claude 仅跟踪指定工具的检查点并不完全相同。
